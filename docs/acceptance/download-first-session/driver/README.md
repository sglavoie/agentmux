# Recorded native acceptance driver

These are the helpers used for the 2026-10-30 MacBook Pro run. They are an
acceptance fixture, with fixed paths and a fixed test bundle ID, rather than
an installer. Every helper requires `AMX_UI_REMOTE_EXECUTION=1`; UI must run
on the operator-approved test Mac. The archived copies also refuse a duplicate
app start and protect capture with the test app's bundle identity.

Copy `scripts/acceptance/packaged-app.py` to `/tmp/packaged-app.py` on that
Mac, the candidate ZIP to `/tmp/Agent-Mux-0.10.0-candidate-macos-arm64.zip`, and
these helpers to `/tmp/amx-firstsession-live.py`, `/tmp/amx-firstsession-facts.py`,
`/tmp/amx-firstsession-ui.applescript`, and `/tmp/amx-firstsession-capture.swift`.
Run them over SSH with the environment flag set. `world.py prepare` refuses an
existing world or preference domain; inspect or clean up the earlier run rather
than deleting something it did not create.

The world is `/tmp/amx-firstsession-1030`: its own HOME, TMPDIR, configuration,
profile hooks, project, daemon, tmux server, app, and preference domain. The
original archive is signature-checked before a UI copy receives a unique bundle
ID and outer ad-hoc signature. A CLI override restores the disposable HOME after
Ghostty's `login(1)`; nested bundled executables retain their original signatures.
The shim also sets TERM, so embedded terminals are verified by process ancestry
and actual input rather than assuming their reported TERM is `xterm-ghostty`.

Use `world.py prepare`, then `start`. An absent config should open the workspace
on Set Up First Project without a running daemon. `ui.applescript press TITLE`
presses a native workspace button or project menu item; `type TEXT` and `return`
send input only after checking the test process's bundle ID and frontmost state.
Always type the disposable project's full path in setup: `login(1)` can reset the
utility's working directory to the account home even if the app itself was
started in the fixture project. After inspecting the summary, return, install
the scripted harness with `world.py fixture`, start the daemon, and launch the
project through the native menu.
If a restart restores the completed setup tab's closed-view placeholder,
`ui.applescript close` closes that view and returns to the launch controls.

The fixture reads `ask`, `work`, `done`, `quit`, or arbitrary echo text. It executes
the real hook commands generated by setup. `facts.py state key`/`state stop`
assert observed daemon states, `input TEXT` checks captured terminal output,
and `record LABEL` retains a lifecycle baseline. After quit/reopen or bundle
replacement, `verify LABEL` compares server generation, runtime ID, agent PID
and start identity and verifies that the attached client descends from the app.
`world.py update` requires the app to have exited, replaces its bundle, and
leaves the session server running.

After ending the fixture, open History with `ui.applescript history` and submit
Resume with `resume`; `facts.py resumed` verifies a new runtime whose argv names
the exact original conversation. The initial transcript lacked `entrypoint`,
so that recorded run enabled Include Automated Sessions before resuming its
unknown-class conversation. The reusable fixture now emits `entrypoint: cli`.
SwiftUI's button labels were not consistently exposed to the recursive AX helper;
the recorded inclusion click used the inspected History window's coordinates,
while Resume used its native ⌘Return shortcut.

`capture.swift LABEL` saves only windows owned by the isolated app, using
`screencapture -l`. It needs the permissions of the process running it; the
recorded SSH route already had them. No privacy grant or screen-sharing setting
was added. Neither `/dev/console` ownership nor a VNC viewer's login screen is
sufficient evidence that the operator session is locked. Check actual UI access
and the logged-in session before asking the operator to unlock anything.

Finish with `world.py cleanup`. It quits only the recorded test app, stops and
checks the isolated backend and daemon, removes its own preferences, and records
the verified result in `cleanup.json`. World
files remain for evidence; remove them only after the processes have stopped and
the `world.json` marker confirms ownership.
